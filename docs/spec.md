# nsf2mid 仕様書

morokoshi の派生アプリ。NSF（ファミコン音楽ファイル）を読み取り、テンポ検出付きで MIDI に変換する。

## 方針

- 既存の nsf2midi（zophar.net）の不満点を解消する
  - テンポ非対応 → フレーム単位の発音タイミングからテンポを検出し、クオンタイズ済み MIDI を出力
  - ノートオン判定が不自然（例: ドラクエ2 の発音中の duty 比変化が再ノートオン扱いになる）
    → duty 変化・音量エンベロープ・ビブラートは同一ノート内の変化として扱う
- 拡張音源は後回し（Phase 5）

## 構成（src/）

| ファイル | 役割 |
|:---|:---|
| `nsf2mid.py` | CLI エントリ。`APP_VERSION` を保持。MIDI 構築・各種出力 |
| `cpu6502.py` | 6502 CPU コア（2A03: 10進モードなし、主要な非公式命令対応） |
| `nsf.py` | NSF ヘッダ解析・メモリマップ・バンク切替・INIT/PLAY 呼び出し・レジスタ書き込み記録。`$4015` 読み出しはライブ APU モデルから返す |
| `apu_state.py` | APU 状態モデル（長さカウンタ・エンベロープ・スイープ・線形カウンタ・フレームシーケンサ・DMC 再生区間）。音声合成はしない |
| `notes.py` | ノート抽出（P1/P2/TRI）・リバーブ余韻判定・グライド統合・テンポ用オンセット |
| `tempo.py` | グリッド検出・拍子（2分割/3分割）判定・テンポマップ・フレーム→ティック変換 |
| `midi.py` | SMF（format 1）書き出し |

## 使い方

```
python src/nsf2mid.py FILE.nsf [-t TRACK] [-s SECONDS] [-o OUTDIR] [--info] [--dump]
                      [--keep-tail] [--no-quantize] [--unit FRAMES] [--rows-per-beat N]
```

| オプション | 内容 |
|:---|:---|
| `-t` | 曲番号（1 始まり、既定はヘッダの開始曲） |
| `-s` | エミュレートする秒数（既定 120） |
| `--dump` | Phase 1 のダンプ（writes/frames/tracker）も出力 |
| `--keep-tail` | リバーブ余韻もノート長に含める（既定は余韻の直前でノートオフ） |
| `--no-quantize` | グリッドへのスナップをしない（テンポには合わせる） |
| `--unit` | グリッド単位（フレーム数）を手動指定 |
| `--rows-per-beat` | 1 拍あたりの行数を手動指定（4 = 16分音符グリッド） |

出力（既定: NSF と同じフォルダの `nsf2mid_out/`）:

| ファイル | 内容 |
|:---|:---|
| `*.mid` | MIDI（Track0: テンポマップ・4/4、Track1-3: Pulse1 / Pulse2 / Triangle、ch 1-3） |
| `*_notes.csv` | 抽出ノート一覧（開始/ゲート終了/終了フレーム・余韻長・音名・ピーク音量・開始要因・ティック・音量推移） |
| `*_writes.csv` | （`--dump`）全 APU レジスタ書き込み |
| `*_frames.csv` | （`--dump`）フレーム末尾時点の各チャンネル状態 |
| `*_tracker.txt` | （`--dump`）トラッカー風の目視確認用ビュー |

トラッカー表示の記号:
- `*` = 周期上位レジスタ（$4003/$4007/$400B/$400F）への書き込み（位相リセット・エンベロープ再始動）
- `d` = duty 比変化 / `p` = 上位レジスタ書き込みなしの周期変化 / `~` = 平均律から 20 セント超ずれ
- 実効音量 0 でも `*` があれば `v0` 付きで表示

## Phase 2 ノート判定

### 調査結果（ドライバごとの癖）

| 曲 | 観察 | 判定への反映 |
|:---|:---|:---|
| ドラクエ2 | 発音中に duty が D1→D2→D1→D0 と変化。`$4003` は書かれない | duty 変化ではノートオンしない |
| ドラクエ2/3 | ゲートオフで音量が急落し、D0・音量 2 の余韻が次の音まで続く（同じ音程） | 余韻として判定しノートオフ |
| ドラクエ4 | ゲートオフで音量 E→7 に急落し、その後ゆっくり減衰 | 同上（急落） |
| マリオUSA | 音量が B→1 まで減衰し、音量 1 で次の音まで保持 | 同上（低い床で保持） |
| ドラクエ3 / 2 街 | 発音中に音量が上下（トレモロ B→8→B） | 音量上昇ではノートオンしない |
| オホーツクに消ゆ | 音量が B,B,4,4,A,A,5,5,9,9,6,6… と 2 フレームごとに上下する減衰トレモロ。連打に聞こえるが `$4003` 書き込みは 1 回 = 1 音 | 同上 |
| オホーツクに消ゆ | 発音前に `$4015` を書き換えて**読み戻す**ドライバ | `$4015` 読み出しを実装（未実装時は無音になっていた） |
| スーパーマリオ | `$4003` 書き込みと同フレームで音量 0、次フレームから発音 | 無音フレームのトリガーを保留し、同じ音程で鳴り始めたらトリガーフレームを開始とする |
| ロックマン2 | 各音の直前に周期 0 でトリガー（無音）。三角波でピッチ急降下のドラム | 周期範囲外は無音扱い。短いピッチ変化の連鎖は 1 音に統合 |
| ドラクエ2 序曲 | チャンネル間で発音が 1 フレームずれることがある | テンポ検出時は 1 フレーム以内のオンセットを統合 |

※ ユーザー指摘の「発音終了後に直前の音程を小さい音量で鳴らすリバーブ」は、調査した DQ2/3/4・マリオUSA では
  **同じ音程のまま音量だけを落として鳴らし続ける**方式だった（再トリガーなし・別音程なし）。

### ノートオン
1. `$4003/$4007/$400B` 書き込み（ハードウェアトリガー）。無音フレームでのトリガーは 2 フレーム以内に同じ音程で鳴り始めればトリガーフレームを開始とする
2. 音程が 0.75 半音以上離れ、2 フレーム以上続いた
3. 無音 → 発音
- 発音フレームの 6 割超でトリガーするドライバはトリガーを判定に使わない

### 余韻（ゲートオフ）判定
ノートの音量列で、次をすべて満たす最初のフレーム g を余韻の開始とする:
- g 以降の音量がすべて vol[g] 以下（再上昇しない）
- vol[g] ≤ ピーク / 2
- 直前から 3 以上急落、または vol[g] ≤ max(2, ピーク / 4)
- 余韻が 2 フレーム以上残る

### グライド統合・最短長
- 3 フレーム以下のノートに続く、隣接した音程分割ノート（3 フレーム以下）は統合する
- 1 フレーム以下のノートは捨てる

## Phase 2 テンポ検出

1. **グリッド検出**: 2〜48 フレームの単位候補（0.2% 刻み＋整数/半整数）について、円周平均で位相を求め、許容誤差内のオンセット率を偶然一致率で補正したスコアで評価。最良スコアから 0.08 以内で最大の単位を採用。整数に十分近ければ整数にスナップ
   - ドラクエ系のテンポ累積型ドライバは 14.4 フレームのような小数単位になる
2. **2分割/3分割判定**: オンセット間隔（単位数）の過半数が 3 の倍数なら 3 分割（3連・シャッフル）
   - 2 分割: 1 拍 = 4, 2, 8, 16 行 / 3 分割: 12, 6, 3, 24 行のうち、BPM が 70〜170 に入る最初のもの
3. **テンポマップ**: 8 秒窓ごとに全体グリッドの当てはまりを確認し、合わない窓は個別にグリッド検出（全体単位の 1/2.2〜2.2 倍の範囲、スコア 0.6 以上かつ全体より 0.25 以上良い場合）。同じ単位の窓を統合し、境界はオンセット単位で最適化
4. **ティック変換**: PPQ 480。区間ごとに原点（最初のオンセットに最も近いグリッド点）からの行数 × (480 / 行数/拍)

### 既知の課題（今後）
- テンポの倍/半分の曖昧さ（例: スーパーマリオ 100 ⇔ 200 BPM）。`--rows-per-beat` で手動補正可
- 小節頭（ダウンビート）の検出は未実装。最初の音を 0 ティックに置く
- ピッチベンド出力（ビブラート・スライド）は未実装
- 三角波ドラム（ロックマン2 等）は現状 1 音として出力。Phase 3 でドラム化を検討
- 曲の終端・ループ検出は Phase 3
