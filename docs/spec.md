# nsf2mid 仕様書

morokoshi の派生アプリ。NSF（ファミコン音楽ファイル）を読み取り、テンポ検出付きで MIDI に変換する。

## 方針

- 既存の nsf2midi（zophar.net）の不満点を解消する
  - テンポ非対応 → フレーム単位の発音タイミングからテンポを検出し、クオンタイズ済み MIDI を出力
  - ノートオン判定が不自然（例: ドラクエ2 の発音中の duty 比変化が再ノートオン扱いになる）
    → duty 変化・音量エンベロープ・ビブラートは同一ノート内の変化として扱う

## 構成（src/）

| ファイル | 役割 |
|:---|:---|
| `nsf2mid.py` | CLI エントリ。`APP_VERSION` を保持 |
| `cpu6502.py` | 6502 CPU コア（2A03: 10進モードなし、主要な非公式命令対応） |
| `nsf.py` | NSF ヘッダ解析・メモリマップ・バンク切替・INIT/PLAY 呼び出し・レジスタ書き込み記録 |
| `apu_state.py` | APU 状態モデル（長さカウンタ・エンベロープ・スイープ・線形カウンタ・フレームシーケンサ・DMC 再生区間）。音声合成はしない |

## Phase 1 の使い方

```
python src/nsf2mid.py FILE.nsf [-t TRACK] [-s SECONDS] [-o OUTDIR] [--info]
```

出力（既定: NSF と同じフォルダの `nsf2mid_out/`）:

| ファイル | 内容 |
|:---|:---|
| `*_writes.csv` | 全 APU レジスタ書き込み（フレーム番号・フレーム内サイクル・アドレス・値） |
| `*_frames.csv` | フレーム末尾時点の各チャンネル状態（音程・セント・実効音量・duty・長さカウンタ・そのフレームで書かれたレジスタ） |
| `*_tracker.txt` | トラッカー風の目視確認用ビュー |

トラッカー表示の記号:
- `*` = 周期上位レジスタ（$4003/$4007/$400B/$400F）への書き込み（位相リセット・エンベロープ再始動）
- `d` = duty 比変化 / `p` = 上位レジスタ書き込みなしの周期変化 / `~` = 平均律から 20 セント超ずれ
- 実効音量 0 でも `*` があれば `v0` 付きで表示（SMB のように同フレームで音量 0 → 次フレームから発音するドライバ対策）

## Phase 1 で確認できた知見（Phase 2 のノート判定設計用）

- **ドラクエ2**: 発音中に duty が D1→D2→D1→D0 と変化し、末尾は D0・音量 2 の余韻になる。この間 `$4003` は書かれない
  → 「`$4003` 書き込み or 周期の大きな変化」をノートオン候補とし、duty 変化単独ではノートオンにしない
- **スーパーマリオ**: `$4003` 書き込みと同フレームで音量 0 を書き、次フレームから音量が立ち上がる
  → ノートオン判定はトリガーフレーム基準、音量は数フレーム先まで見る
- 同じ音程の連打は `$4003` 書き込みでしか区別できない（DQ2 序曲冒頭など）
